# DrissionPage 元素捕获器 · Chrome 扩展安装文档

> 适用：Chrome 100+ / Edge 100+（Chromium 内核）。已在 **Chrome 156** 实测通过。

---

## 一、准备工作

### 1. 确认扩展文件完整

项目里应当存在 `extension/` 目录，且内容如下（缺一个都会加载失败）：

```
extension/
├─ manifest.json      ← 必须有，扩展清单
├─ background.js      ← 必须有，后台脚本
├─ picker.js          ← 必须有，拾取器
├─ panel.js           ← 必须有，面板逻辑
├─ panel.css          ← 必须有，面板样式
└─ icons/
   ├─ icon16.png
   ├─ icon48.png
   └─ icon128.png
```

> `panel.html` 是可选的独立页面，正常使用不需要它。

### 2. 找到扩展所在路径

在本项目根目录执行，可打印出用于选择的绝对路径：

```bash
cd "D:\SwagTslldLocalAIProject\python网页drissionpage库元素捕获器"
```

安装时要在文件选择框里选中 **`extension` 这个文件夹本身**（不是里面的某个文件）。

## 二、安装步骤（手动，推荐）

### 第 1 步：打开扩展管理页

在 Chrome 地址栏输入以下任一地址并回车：

- `chrome://extensions`
- Edge 用 `edge://extensions`

### 第 2 步：开启开发者模式

页面**右上角**有一个「**开发者模式**」开关，把它打开。
打开后，页面顶部会多出三个按钮：`加载已解压的扩展程序` / `打包扩展程序` / `更新`。

### 第 3 步：加载扩展

点击「**加载已解压的扩展程序**」，在弹出的文件夹选择框中：

1. 定位到项目目录
2. **选中 `extension` 文件夹**
3. 点「选择文件夹」

### 第 4 步：确认加载成功

扩展列表里应出现一张卡片：

- 名称：**DrissionPage 元素捕获器**
- 版本：1.0.0
- 状态：已启用（开关为蓝色/打开）

如果卡片上有红色「错误」按钮，点击它可以看到具体报错（见下方「常见问题」）。

### 第 5 步：固定到工具栏（重要）

点击浏览器工具栏右侧的「**拼图图标**」（扩展程序菜单），
在列表里找到「DrissionPage 元素捕获器」，点它旁边的**图钉**图标。

固定后，工具栏上会常驻一个 **DP** 蓝色图标 —— 这就是面板开关。

---

## 三、（可选）允许访问本地文件

扩展默认只能注入 `http://` / `https://` 页面。
如果你需要捕获**本地 HTML 文件**（`file:///...`），要额外授权：

1. 打开 `chrome://extensions`
2. 找到「DrissionPage 元素捕获器」，点「**详情**」
3. 向下找到「**允许访问文件网址**」
4. 把它打开

> 不需要捕获本地文件的话，这一步可以跳过。

## 四、开始使用

### 打开面板

在任意网页上，点工具栏的 **DP** 图标，页面右侧会滑出面板。

> 第一次在某类网站上使用时，Chrome 可能提示「此扩展程序可以读取和更改您在此网站上的所有数据」。
> 这是 `host_permissions: <all_urls>` 的正常提示，选择允许即可。

### 拾取元素

1. 面板里点「**开始拾取**」（按钮变绿，显示「拾取中…点页面元素」）
2. 鼠标在页面上移动 —— 元素会出现**蓝色高亮框**，上方有标签和定位提示
3. **点一下**目标元素 —— 框变绿色，面板立刻填充内容
4. 需要继续拾取就再点一次「开始拾取」

### 快捷键

| 按键 | 作用 |
| --- | --- |
| `Alt + P` | **一键开始拾取**：面板未打开时自动弹出，并直接进入拾取模式 |
| `Esc` | 退出拾取模式 |

### 面板五个标签页

| 标签 | 内容 |
| --- | --- |
| **元素** | 标签/id/class/文本/value/位置/评级、全部 HTML 属性、父级链（点任意一层可切换目标） |
| **定位** | 所有候选表达式，带匹配数量、结论和 A–D 等级；底部可手写表达式回车校验 |
| **代码** | 完整可运行脚本 / 定位片段 / 8 类常用写法（等待、点击、输入、读取、断言、滚动、截图、批量遍历） |
| **测试** | 直接在当前页执行动作：点击、双击、右键、JS 点击、悬停、聚焦、输入、清空、勾选、取文本/HTML/属性/value/状态/位置/样式 |
| **列表** | 把多个元素 + 动作攒成一份脚本，一键导出 |

### 怎么看定位结论

| 结论 | 含义 | 能不能用 |
| --- | --- | --- |
| **推荐 / 可用** | 唯一匹配，且确认首个匹配就是你点的元素 | 放心用 |
| **不唯一** | 匹配多个，但首个正好是目标 | 能用 |
| **错位** | 首个匹配**不是**你点的元素 —— 脚本会操作错对象 | 别用 |
| **未匹配** | 页面上找不到 | 别用 |
| **语法错误** | 表达式无法解析 | 别用 |

## 五、更新扩展

改动了 `extension/` 里的文件后：

1. 打开 `chrome://extensions`
2. 找到扩展卡片，点「**重新加载**」（圆形箭头图标）
3. **刷新目标网页**（重要，否则页面里还是旧代码）

## 七、常见问题

### Q1：装了扩展但工具栏没有 DP 图标 ⭐最常见

**这几乎总是「没固定到工具栏」，不是扩展坏了。** Chrome 出于安全考虑，
新装的扩展默认只出现在「扩展程序」菜单里，不会自动占用工具栏位置。

**确认扩展本身是否正常**：打开 `chrome://extensions`，能看到「DrissionPage 元素捕获器」
卡片、开关是蓝色、卡片左侧有蓝色 DP 图标 → 扩展是好的，只是没固定。

**三种打开面板的方式，任选其一：**

1. **直接按 `Alt + P`**（最省事，推荐）
   已在扩展里注册全局快捷键，无需图标。按下去**面板会自动弹出并直接进入拾取模式**，
   连「点开始拾取」这一步都省了。再按一次 `Alt+P` 退出拾取（面板保留）。

2. **从扩展菜单打开**
   点地址栏**右侧的拼图图标**（扩展程序菜单）→ 在弹出列表里点「DrissionPage 元素捕获器」
   → 面板立即打开。这个列表里一定能看到它。

3. **固定图标到工具栏（一次性设置）**
   点拼图图标 → 在「DrissionPage 元素捕获器」这一行**右侧点图钉图标** →
   图标固定后就会常驻工具栏，以后一键打开。

> 说明：`launch_extension.py` 启动的 Chrome 会尝试把固定状态写进 profile，
> 但 Chrome 对 pin 状态有完整性校验，不一定生效。所以**优先用 `Alt+P`**。

**如果 chrome://extensions 里根本没有卡片**：说明扩展没加载成功，
点「加载已解压的扩展程序」重新选择 `extension` 文件夹。

### Q2：点图标后没有任何反应

按顺序排查：

1. **当前是否为浏览器内部页面？** `chrome://`、`edge://`、扩展商店、`about:` 这些页面浏览器禁止注入脚本，扩展无法工作。换一个普通网页再试。
2. **是否刚装完扩展但页面没刷新？** 安装/重载扩展后，已打开的页面需要刷新一次。
3. **是否为本地文件？** `file:///` 页面需要在扩展详情里开启「允许访问文件网址」。
4. 打开 `chrome://extensions`，点扩展卡片上的「错误」按钮看有无报错。

### Q3：面板出现了，但「开始拾取」点了没反应

先确认按钮已变绿（显示「拾取中…」）。若仍无高亮：

- 刷新页面后重试
- 页面可能禁止了脚本注入（极少数站点有 CSP 限制），换其他网站验证扩展本身是否正常

### Q4：拾取到了元素，但定位是 D 级 / 提示「错位」

这说明这个表达式不可靠，不是扩展出问题。请看「定位」页里等级更高的候选：

- **A / B 级**优先：通常是 `id`、`data-*` 属性、语义化 class
- **D 级**多半是十几层深的 `css:html>body>div:nth-of-type(3)...`，页面一改版就失效
- 若所有候选都是 D，说明该元素本身没有任何语义属性（常见于自动生成的框架页面），可以用文本框手写 `tx=某段文字` 之类更稳的写法

### Q5：影子 DOM（Shadow DOM）里的元素能捕获吗

能。拾取器会穿透 open shadow root，生成的代码形如
`page.ele('#host').shadow_root.ele('#btn')`。

### Q6：iframe 里的元素能捕获吗

能。拾取器会注入到所有 frame。但生成的代码里需要自己补 `page.get_frame('#框架选择器')`，因为扩展拿不到 DrissionPage 的页面层级对象。

### Q7：提示"manifest file is missing or unreadable"

说明选错了文件夹 —— 必须选 **包含 `manifest.json` 的那一层**（即 `extension` 文件夹本身）。

### Q8：和桌面版（run.py / exe）有什么区别，该用哪个

| | Chrome 扩展 | 桌面版 |
| --- | --- | --- |
| 用哪个浏览器 | **你自己的** | 独立的受控 Chromium |
| 登录态 | 直接可用 | 需要自己登录 |
| 是否看镜像 | 不需要，就是当前页面 | 有实时镜像画面 |
| 定位校验 | 浏览器内 JS 实现 | Python + DrissionPage 真解析 |
| 适合 | 日常抓取、调试有登录态的站点 | 需要隔离环境、批量自动化 |

**两者可以同时装，互不干扰。**

### Q9：怎么用启动脚本自动装好扩展

```bash
F:\Miniconda39\envs\python31013\python.exe launch_extension.py
```

脚本会启动一个使用独立配置目录（`.chrome-profile/`）的 Chrome，
并通过 CDP 自动加载扩展、打开演示页。不影响你日常浏览器的数据。

> 为什么脚本不用 `--load-extension`：Chrome 137+ 会忽略这个命令行参数，
> 必须以 CDP 的 `Extensions.loadUnpacked` 加载。

## 八、权限说明

扩展申请的权限及用途：

| 权限 | 用途 |
| --- | --- |
| `activeTab` | 点击图标时访问当前标签页 |
| `scripting` | 注入拾取器与面板脚本 |
| `storage` | 保存你输入的文本、捕获列表等设置 |
| `clipboardWrite` | 「复制代码」按钮 |
| `tabs` | 定位当前活动标签页（用于注入） |
| `host_permissions: <all_urls>` | 在任意网站上工作 |

**扩展不联网、不上传任何数据**：全部代码本地执行，没有远程请求。
生成的 Python 代码只存在你的剪贴板/下载文件里。
